# Wage App Backend

🚧 **Статус проекта: активная разработка (используется в продакшене)**

Backend-сервис для **расчёта заработной платы сотрудников** с поддержкой сохранения отчётов в течение дня и последующего расчёта итогов на сервере.

Проект является развитием более простой версии *salary app* из резюме — с переходом к реактивной архитектуре и усложнением логики расчётов.

---

## 📌 Описание

Сервис предназначен для:
- фиксации рабочих событий/отчётов в течение дня
- хранения промежуточных данных на сервере
- расчёта итоговой заработной платы 
- агрегация и экспорт данных о выплатах работникам
- отправки уведомлений через Telegram-бота

Клиентская часть — отдельное web-приложение на **Next.js + React**.  
Уведомления отправляются через отдельный сервис **wage-app-tg-bot**.

---

## ⚙️ Основной функционал

- 📥 Приём и сохранение дневных отчётов
- 📊 Расчёт зарплаты на основе накопленных данных
- 🔄 Серверная агрегация и обработка логики
- 🔔 Интеграция с сервисом для уведомлений в Telegram
- 🌐 API для фронтенд-клиента

---

## 🏗 Архитектура

Проект включает следующие сервисы:
- wage-app-backend - основной backend-сервис (текущий репозиторий)
- wage-app-web - web-клиент
- wage-app-tg-bot - сервис отправки нотификаций Telegram

Межсервисное взаимодействие реализовано через REST.

Для аутентификации и авторизации используется Keycloak.

Особенности архитектуры wage-app-backend:
- Реактивный backend на **Spring WebFlux + Coroutines**
- Асинхронная работа с БД через **R2DBC**
- Чёткое разделение модулей:
    - domain - доменная логика
    - application - основное приложение состоящее из классических слоев: controller, service, data
    - config - глобальная конфигурация
    - messaging - принимает события и отправляет соответствующие сообщения

## 💡 Особенности реализации

- Использование coroutines вместо Reactor API для более читаемого кода
- Полностью неблокирующий стек (WebFlux + R2DBC + WebClient)
- Перенос сложной логики расчётов на сервер
- Баланс между микросервисной архитектурой и монолитным подходом: ядро бизнес логики находится в одном сервисе, отдельный функционал (авторизация, уведомления) - в отдельных.

## 🏢 Реальное применение

Сервис используется в реальной эксплуатации на предприятии (небольшой ресторан).

- 👥 Количество пользователей: до 10 человек
- ⏳ Время стабильной работы: более 3 лет (включая старую версию приложения - SalaryApp)

Система применяется для ежедневного учёта и расчёта заработной платы сотрудников, включая сохранение промежуточных отчётов и формирование итоговых данных.

## Release automation

Pull requests and protected branches run the complete test/build contract. An
annotated `vX.Y.Z` or `vX.Y.Z-U<N>` tag on the matching `release/X.Y.Z` line
publishes immutable version and `git-<sha>` Docker tags, records the registry
digest, and opens an image-only pull request in `wage-app-infr`.

The owner provisions the repository-scoped GitHub App without sharing its key
with an agent or committing it:

```shell
./scripts/setup-backend-release-promoter.sh
```
